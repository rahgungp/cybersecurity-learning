PRACTICAL LAB · MINGGU 11 · MODULE 11

Vulnerability Assessment

⏱ 60 menitIndividual / Kelompok 2 Output: Vulnerability Assessment ReportTools: Nmap, NVD
📌 Hubungan dengan Materi: Praktik ini menerapkan siklus vulnerability management dari Module 11 pada target lab lokal yang sah, melanjutkan kemampuan scanning dari Module 03 dan 06.

🎯 Objective

Mahasiswa mampu melakukan vulnerability scanning pada target lab, memvalidasi temuan, dan menyusun prioritas remediasi berbasis risiko.

⚠️ Safe Lab Rule: WAJIB dilakukan pada target lab lokal yang sah (mis. Metasploitable2/3, atau VM sengaja rentan lain). Dilarang keras scanning terhadap IP/domain publik tanpa izin eksplisit tertulis.

ASSET DISCOVERY & SCANNING

Jalankan Nmap dengan script vuln terhadap target lab untuk menemukan port, layanan, dan versi software.

$ nmap -sV --script vuln [IP_TARGET_LAB]

IDENTIFIKASI CVE

Untuk minimal 3 layanan/versi yang ditemukan, cari CVE yang relevan pada NVD (nvd.nist.gov) dan catat CVSS score-nya.

VALIDASI TEMUAN

Untuk setiap CVE, verifikasi apakah versi yang terdeteksi benar-benar cocok dengan detail CVE (bukan false positive) — periksa deskripsi CVE dengan cermat.

PERIKSA STATUS CISA KEV

Untuk setiap CVE yang ditemukan, periksa apakah terdaftar di CISA KEV Catalog.

PRIORITAS & REKOMENDASI

Susun prioritas remediasi berdasarkan kombinasi CVSS + status KEV + exposure (asumsikan target ini internet-facing untuk latihan), dengan rekomendasi konkret.

📋 EXPECTED OUTPUT — Vulnerability Assessment Report

  • Hasil scanning (output Nmap + tabel port/layanan/versi)
  • Minimal 3 CVE relevan dengan CVSS score dan deskripsi singkat
  • Catatan validasi (konfirmasi bukan false positive)
  • Status CISA KEV untuk setiap CVE
  • Tabel prioritas remediasi: CVE ID, Severity, Affected Asset, Risk, Recommendation

Pertanyaan Analisis

  1. Dari CVE yang kamu temukan, mana yang PALING mendesak ditambal, dan apa faktor penentu keputusanmu (bukan CVSS semata)?
  2. Apakah ada kemungkinan false positive dari hasil scan? Bagaimana kamu memverifikasinya?
  3. Jika target ini adalah server produksi sungguhan, kendala apa yang mungkin dihadapi tim IT saat ingin segera menambal (mis. downtime, testing kompatibilitas)?
